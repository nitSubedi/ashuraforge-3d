# Cane-Sword Stance — Design

**Date:** 2026-09-27
**Status:** Approved (design), pending implementation plan
**Builds on:** the phase-timed combat rework in `scripts/player.gd` (measured strike
windows, lunge, hitstop, input queue) — see `2026-06-29-cane-capoeira-combat-design.md`.

## Goal

The cane is currently a static prop. Make it a real **cane-sword**: the hero can
draw a hidden blade from the shaft and fight with it, and can flash it out for a
quick-draw strike without leaving cane stance. Must keep the fluidity of the
current combat (it inherits the same move machinery).

## Player-facing behaviour

| Stance | J (attack) | K (kick) | Q |
|---|---|---|---|
| **Cane** (default) | cane string h1→h2→h3→**iai** | capoeira string (unchanged) | draw → sword stance |
| **Sword** | sword string s1→s2→s3(→s4) | capoeira string (same kick nodes) | sheathe → cane stance |

- **Draw / sheathe** are short moves. Each has a measured `swap` time — the frame
  the right hand reaches the shaft — at which the blade actually changes place.
  Dodge may cancel them **before** `swap`, not after (no half-drawn states).
- **Iai quick-draw:** the 4th hand press in cane stance. The blade appears at the
  draw frame, cuts as a `heavy` move (big hitstop + shake), and returns to the
  shaft at the move's recovery. The hero stays in cane stance.
- Cross-branching hand↔foot works in both stances (sword nodes' `foot` → kick
  nodes; kick nodes' `hand` → the current stance's hand string).
- Locomotion clips are shared across stances, except a sword-stance **idle**.
- Walking-stick grip (existing) applies only in cane stance.

## Weapon

Replace the code-built crook in `build_hero.gd` with the Blender cane, split into
two parts (regenerated by `tools/gen/make_cane.py`):

1. **Sheath** — lacquered shaft + ferrule (everything below the collar).
2. **Hilt + blade** — crook handle + silver collar + the new blade.

**Blade:** slim Victorian **estoc** — straight, narrow, triangular section, bright
steel with an engraved fuller, length ≈ shaft interior (~0.75 m) so it plausibly
lives inside it. Its own steel material (metallic ~1, roughness ~0.2).

**Attachment (built into `hero.tscn` by `build_hero.gd`):**
- `RightHandMount` (BoneAttachment3D, RightHand) — hilt+blade always here.
- `LeftHandMount` (BoneAttachment3D, LeftHand) — sheath when drawn.
- **Sheathed:** sheath is parented under the hilt so the assembly reads as one
  cane (blade hidden inside). **Drawn:** sheath reparents to `LeftHandMount` with
  its own grip transform. Swapping = reparent with a stored local transform.

## Animation clips (Mixamo, "Without Skin", X Bot rig)

Downloaded with the existing standalone scripts in `mixamo-mcp/tools/`
(**the mixamo MCP must be disconnected while they run** — shared browser profile).
Target set; exact picks decided by what Mixamo returns:

- Draw: "Draw Sword 1" / "Draw Sword 2" → `sword_draw`
- Sheathe: "Sheath Sword 1" / "Sheath Sword 2" → `sword_sheathe`
- Slashes (3–4, one-handed): "Stable Sword Inward Slash", "Stable Sword Outward
  Slash", "Sword And Shield Slash 2", "Standing Melee Attack Downward" → `sword_1..4`
- Iai: a fast draw-slash (e.g. a draw clip that ends in a cut, or an outward
  slash started from a low hip pose) → `iai`
- Idle: "Sword And Shield Idle" / "Standing Idle (sword)" → `sword_idle`

All merged by `build_hero.gd` (root motion stripped as today) and timed by
`tools/measure_strikes.gd` (extended with a `swap` measurement: right-hand
closest approach to the left hip for draw/sheathe clips).

## Code structure (`scripts/player.gd`)

- `_stance: String` = `"cane"` | `"sword"`.
- `_nodes` gains `s1..s4`, `iai`, `draw`, `sheathe` entries using the existing
  schema (`lead`, `hits`, `end`, `wind`, `heavy`) plus optional `swap` (clip s)
  and `stance_to` (for draw/sheathe). Neutral entry per stance:
  `NEUTRAL = {"cane": {"hand": "h1", "foot": "f1"}, "sword": {"hand": "s1", "foot": "f1"}}`.
- A kick node's `hand` target resolves against the current stance
  (`"@hand"` sentinel → the stance's hand neutral), so kicks chain back into
  cane *or* sword strings.
- `_update_attack` fires `_swap_weapon()` once when `t >= swap`; `iai` uses
  `swap` to show the blade and its `end` to re-sheathe.
- New `_weapon_state(drawn: bool)` owns all reparenting/visibility — one place.
- `draw`/`sheathe` have no `hits`; they reuse phase playback (fast wind, brisk
  recovery) and the movement-cancel rule.

## Testing

- `tools/measure_strikes.gd` over the new clips → timing table (committed into `_nodes`).
- `tools/sim_combo.gd` gains `q` in `SIM_INPUT` (stance toggle). Headless runs:
  `qhhhhq` (draw, sword string, sheathe), `hhhh` (iai), `qhkhq` (cross-branch in
  sword stance). Assert every strike hits and stance ends where expected.
- `SIM_SHOT=1` renders: mid-draw, a sword hit, the iai cut — check the blade
  leaves/enters the shaft cleanly and the sheath sits in the left hand.
- User playtest.
